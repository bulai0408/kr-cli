# kr-cli 规格

2026-10-14，由 owner 与协调者五轮访谈确定；同日 owner 梳理第二、三阶段后更新。设计理由见 `docs/adr/`，依据见 `docs/research/`。

## 定位

kr 是 owner 个人的开发流程执行层，把 owner 的最佳实践变成可执行、可检查的步骤：按机器性能平衡效率和质量、管理各种环境、让 agent 能放心地自己完成更多事。它与开发工具无关，只支持 Apple 客户端项目。

## 模型

| 部分 | 内容 |
|---|---|
| 机器档案 | 运行时检测能力和状态，推算资源容量；可按机器覆盖（ADR 0003） |
| 环境 | Xcode 版本、模拟器运行时、模拟器池、签名、测试服务器、凭证位置（只记位置） |
| 流程 | 预检 → 构建 → 运行 → 核对 → 门禁，每步产出事件 |
| 工具层规则 | kr 自己领域里的硬底线（只碰池内设备、数据隔离、凭证不出日志）写在各命令里；信任和权限由 owner 和 agent 宿主管理（ADR 0012） |
| 适配器 | 远程机器（第二阶段，用户声明的 SSH 主机）、真机（第三阶段）。kr 不接编排工具和记忆系统（ADR 0002、0007） |

## 第一阶段（P0）

目标：Krill 第 7 批完全用 kr 跑自验和门禁。

### 1. 资源层（ADR 0004）
- 资源 `build`、`sim`、`light`，容量来自机器档案；文件锁槽位，崩溃自动释放。
- 跨项目先来后到队列；`kr queue` 显示占用者（项目、任务、进程、开始时间）、等待者和预计等待时间。
- `kr lock <resource> -- <command>`：拿到槽位后执行一条命令，结束立即归还。

### 2. 机器档案与 `kr doctor`（ADR 0003）
- 检测：芯片、核数、内存、磁盘余量、1/5/15 分钟负载、内存压力、已装 Xcode 与当前选择、模拟器运行时、模拟器池是否齐全。
- 检查项目配置要求的 Xcode 版本和运行时是否存在（避免 Xcode 26/27 混用导致的假红，pitfalls E2/E3）。
- 输出建议的资源容量。负载默认不阻塞：只在内存压力 critical 时等待；每项采样负载，高负载期间的失败整项重跑一次（ADR 0003 补充）。

### 3. 模拟器池
- 每个项目一组 `<项目>-Verify-<N>`，按配置的设备型号和运行时创建；kr 只创建、启动、关闭、抹除池里的设备。
- 租约与 `sim` 槽位绑定，结束时关机归还；同时运行的模拟器数不超过 `sim` 容量。

### 4. 项目配置 `.kr.toml`
- `xcode`：要求的 Xcode 版本（kr 用对应的 `DEVELOPER_DIR` 执行）；`platforms`；`project`（含生成命令，例如 `xcodegen generate`）。
- `suites`：三种步骤——`build`（编译某平台）、`test`（测试目标或包测试，可带过滤）、`command`（任意命令，例如后端测试）。
- `scenarios`：UI 场景注册（名称 → 测试类、所需设备类型如 iPad）。这是场景清单的唯一来源。
- `gates`：命名门禁，由套件和场景组成，例如 `default`、`smoke`。
- `isolation`：测试 bundle 标识与权限要求（用于数据隔离检查）。

### 5. `kr check`（预检，ADR 0005）
不占模拟器，只占 `build` 槽位：
- 运行项目的生成命令；
- 用 App 自身的编译设置真编译：包 scheme 和 App 都用 `build-for-testing -destination generic/platform=…`（不用 `swift build`，ADR 0005 补充）；
- 用测试 bundle 的符号静态核对过滤能匹配到测试（运行时 `kr run` 再做真实枚举，ADR 0005 补充）；
- 数据隔离静态检查：测试用的 bundle 必须是配置里声明的合成标识，权限只能指向允许的环境（例如 CloudKit Development）。
失败就返回非零，agent 不应进入运行队列。

### 6. `kr run` 与 `kr gate`（ADR 0005）
- `kr run <场景|套件...>`、`kr gate [名字]`。
- 构建一次：测试产物按输入哈希缓存；构建完归还 `build`，再按 `sim` 容量租模拟器，按历史耗时分配场景并行运行。
- 超时看门狗：每个场景有硬超时，超时即终止并判失败。
- 运行前枚举测试，0 条即失败；运行后从 xcresult 核对测试数、读取真实退出码。
- 默认 `-collect-test-diagnostics never`、`-skipMacroValidation`。
- 失败的测试单独重跑一次：通过记偶发，仍失败记失败。
- 人读输出：每个场景/套件一行 `PASS:` / `FAIL:`，失败最多 3 行摘要和 xcresult 路径；`--json` 输出结构化结果。

### 7. 事件记录
- 每次运行把事件写到 `~/.local/state/kr/events/` 下的 NDJSON：排队开始、拿到槽位、负载等待、构建开始/结束/缓存命中、场景开始/结束/结果、重跑、归还。
- 第一阶段只记录，不做报告命令；记录要足以算出「排队时间 / 运行时间」和每个场景耗时。

### 第一阶段验收
- 用 Krill 第 7 批实测，对比第 6 批：拿到锁后才发现编译失败 0 次；假通过 0 次；排队时间占比明显下降；计时不再手工拼。
- Krill 仓库加入 `.kr.toml`，`e2e.sh` / `test.sh` 不再需要（kr 不可用时可临时回退旧脚本）。

## 第二、三阶段（P1、P2）

2026-10-14 owner 梳理确定：两个阶段在同一波里全部做完，先第二阶段，后第三阶段。

### 要解决的问题
第一阶段让 Krill 第 7 批用上了 kr，实测也暴露了下一步的问题：
- 一次跑完的运行会丢掉结论、失败重跑过滤命中 0 条、收到 SIGTERM 停不下来、产物在运行途中被删时整次失败。
- 需要判断的地方（失败是什么类型、要不要加跑、冲突怎么解）没有结构化地交给 agent，也没有记录和事后对账。
- 选测、合并、批次复盘、交付报告、偶发记录都还靠 agent 或协调者手工完成。
- 只能在本机跑，不能用其他 Mac；不能在真机上跑；每个 worktree 都从零编译。
- kr 的改动只能靠跑完整门禁来评估。

### 解决方式
kr 继续只做确定的事：算出事实、标出需要判断的地方、记录 agent 的决定并对账（ADR 0011）。信任和权限由 owner 和 agent 宿主管理，kr 只管工具层自己的规则（ADR 0012）。具体内容按建议的完成顺序列出。

第二阶段（1–6）：

1. **运行可靠性（实测 bug）**
   - 任何一项的结果文件缺失时，该项判失败并写明缺什么文件，其余项照常给结论。
   - 失败重跑按测试框架生成过滤标识（Swift Testing 保留 `()`）；重跑前先枚举，命中 0 条时报「重跑过滤无效」。
   - SIGTERM 与 SIGINT 处理相同：转发给子进程组，不再开始新场景，归还槽位，记录运行中止事件。
   - 拿到 `sim` 槽位、开始每个场景前再核对测试产物；缺失时回到 `build` 槽位重新构建一次；错误信息写明下一步。
2. **离线评估（ADR 0010）**：`kr plan` 只算不跑；`kr simulate` 复用 kr 自己的调度代码，用虚拟时钟和历史耗时推演；判定重放用当前判定规则重判已保存的运行，只列结论变化；事件补齐 ADR 0010 列出的字段；通道启动顺序固定为先 iPad 后 iPhone。
3. **判断骨架（ADR 0011）**：`--json` 的固定字段 `decisions`；影响结论的判断点以退出码 4 结束；`kr decide` 交回决定并写进事件；对账事件；`kr skill` 输出与版本一致的使用说明，可按项目和个人追加。所有 `--json` 输出带 `schema_version`，字段只加不改。第一个接入的判断点是 `kr run` 中「没见过的失败需要分类」。
4. **选测**：从 `swift package describe --type json` 和工程配置生成模块依赖图；改动文件 → 模块 → 反向闭包 → 场景（场景在配置里声明覆盖的模块）；必跑场景只能加不能删；影响不明确时给出加跑判断点，附历史共同失败统计和偶发率（学习层的第一部分）；`--explain` 说明原因；`kr hash` 调试。
5. **合并辅助**：`git merge-tree` 预测分支冲突；xcstrings 按键三方合并的 merge driver（合并后用 `xcstringstool` 校验）；为每个 worktree 开启 rerere；合并后秒级快检（JSON 解析、场景清单一致、迁移顺序、改动模块增量编译）；合并后凭证扫描；逻辑冲突成为判断点。
6. **远程机器与签名检查**
   - 远程机器是用户在机器配置里声明的 SSH 主机。kr 用系统的 `ssh` 连接，不检查地址、不保存也不读取凭证；连接安全由主机和 owner 负责。
   - 远程主机运行同一版本的 kr，用 git 拉取已推送的分支，结果回传本机；远程主机的资源由它自己的 kr 排队。
   - 远程主机不是装有 Xcode 的 macOS、kr 版本不一致、分支没有推送时，在开始前失败，并写明原因和下一步。
   - 签名检查：回读签名团队、entitlement 和 iCloud 容器环境（Development / Production）；识别 SSH 会话，需要开发者证书签名的任务在 SSH 会话里提前拒绝并说明原因。
第三阶段（7–11）：

7. **`kr report`（含 agent 使用评估）**：从事件生成批次报告——排队/运行时间、返工轮数、偶发排行、每类判断的 agent 判对率，以及 agent 调用了哪些命令、出了几次参数错、哪些判断点判错。报告只提供数据，据此改进 kr 和 `kr skill`，放宽权限由 owner 在宿主里决定。
8. **交付报告草稿**：从一次运行的结果和事件生成「机器判定 / 需人判断手感 / 未验证」三段初稿；能看出的待办自动列入（例如 schema 相关文件改动 → 待部署，真机掉线 → 未验证）。
9. **偶发隔离区**：隔离名单放在项目仓库里，改动经过 PR；名单里的测试照常运行，失败不阻塞门禁，只记录；名单有上限，上限按 `kr report` 统计的偶发频率确定；反复偶发的测试由 kr 以判断点建议加入；进出名单写进事件。
10. **真机流程（最小版）**
    - `kr doctor` / `kr check` 用 `devicectl` 检查真机前置条件：已配对、开发者模式、已启用 UI 自动化、当前 Xcode 支持设备系统版本；缺哪项写明要在设备上做什么。
    - `kr run --device <名字>` 在真机上运行现有场景：构建一次，再在真机上运行；每台真机是一个容量为 1 的资源；kr 不抹掉、不重启、不管理真机。
    - 运行途中设备掉线，该项结果记为「未验证」，不记通过也不记失败。
11. **跨 worktree 编译缓存**：先实测——在 Krill 上对比开和不开 Xcode 原生编译缓存时一批票的总编译时间和假红次数，结论写成 ADR；收益成立就做成功能：`.kr.toml` 开关、同一项目的 worktree 共用缓存目录、事件记录缓存命中、疑似缓存导致的失败用干净缓存重跑一次再判定。实测出现假红或收益很小时，先请 owner 决定。

### 实现决定
- 所有新判断点遵守 ADR 0011：影响结论的以退出码 4 结束（只用于 `check`、`run`、`gate` 及以后的选测、合并辅助），只影响效率的按默认继续并记「待复核」；确定规则（ADR 0003、0005 的偶发规则）留在计算层不变。
- `kr simulate` 与 `kr run` 共用同一份调度代码；调度代码抽到运行库里，接受时钟和执行器，真实运行和模拟只有这两处不同。
- 学习层的统计（共同失败、偶发率、判对率、机器速度）只从事件计算，不调用模型。
- 远程主机在机器配置里声明；本机通过 `ssh` 调用远程的 kr，远程 kr 的 `--json` 输出就是回传结果，事件同时写在两台机器上。
- 结果（Outcome）增加第五种「未验证」，只用于运行途中设备或主机失联；它不算通过。
- 真机是新的资源类型，每台设备容量为 1，不进入模拟器池。
- 编译缓存的取舍以实测 ADR 为准；功能默认关闭，项目在 `.kr.toml` 里打开。

### 测试决定
- 好的测试只看外部行为：退出码、人读输出、`--json` 输出和写出的事件，不测内部函数。
- 主接缝是 `kr` 命令本身：`assert_cmd` 启动真实进程，`KR_REPLAY` 回放录制的真实外部命令输出（xcodebuild、simctl、xcresulttool，以及新加的 `ssh`、`devicectl`），`insta` 快照人读输出。先例是 `kr run` / `kr gate` 的回放测试。
- 回放录制要能带耗时，用于测试「运行中收到 SIGTERM」和「运行中设备掉线」。
- 回放模拟不了的部分用默认不跑、由环境变量打开的真实集成测试：远程用 `ssh localhost` 跑完整流程，并在局域网里的其他 Mac 上验收一次，用 Linux 主机验证「不是 macOS」的报错；真机用 iPad mini 跑一个场景并手动断开一次；编译缓存在 Krill 上实测。
- 每个改变 kr 行为的 PR 按 ADR 0010 附「前后对比」：用离线方法，写明层级和校准误差，不跑完整门禁。

### 不在范围内
- 信任策略（权限分档、批准记录、按证据放宽）：由 owner 和 agent 宿主管理（ADR 0012）。
- 真机截图、性能分析、多台真机并行、CloudKit Production、真实服务场景的凭证注入。
- 把 kr 移植到 Linux。
- 远程执行之外的分布式构建和跨机器共享编译缓存。

## 不做
- 不派单、不和 agent 沟通、不接记忆系统。
- 不判断某台机器允许做什么。
- 不管理信任和权限：这些由 owner 写在 AGENTS.md 和 agent 宿主的权限设置里，kr 只执行工具层自己的规则（ADR 0012）。
- 只按 ADR 0009 桥接旧的全机锁，不兼容旧脚本的其他协议。
- 不在 kr 里调用任何模型（ADR 0011）。
