# 0023 指定池设备与 setup 文件尾换行

状态：已采纳（2026-10-16，#43，协调者已确认）

## 决定

- `kr pool lease` 的 `--name`、`--udid`、显式 `--kind` 三者互斥。未指定时仍按 `default` 类型选空闲设备；名称和 UDID 精确匹配当前项目池，不接收池外设备。
- 指定目标在取资源前核对，池外目标退出 2 并提示 `kr pool status`。候选仅保留该设备，忙时等待，绝不回退其他设备。
- 保留 ADR 0022 的取锁顺序：负载 → 旧锁（若启用）→ sim 槽位 → 池设备锁。队列 task 附带目标，使 `kr queue` 在等槽和等设备阶段都能显示目标；设备锁等待期间继续占用 sim 槽位，与现有租约一致。代价是指定设备忙时占住一个 sim 槽，可能降低其他设备的利用率；指定设备只用于少量兼容路径，接受这个代价。不先等设备再拿槽，避免引入与既有租约不同的反向取锁顺序；统一顺序不产生锁等待环。
- 租约事件及 `--json` 的租约通知携带 `selection: {by, value}`，by 为 name、udid 或 kind。命令 stdout 和退出码继续透传；JSON 租约通知写 stderr，与排队通知一致。
- `kr setup` 安装、替换和卸载规则块后，非空且确实修改的规则文件末尾补 LF；这是标记外逐字保留的唯一例外。重复操作不继续增加换行；只含规则块的文件卸载后删除。无块的卸载不修改文件。

## 验证

通过真实 `kr` CLI、KR_REPLAY、进程竞争和输出/事件断言验证。没有 Apple 构建或完整门禁；真实租约为可选补充。参考 ADR 0004、0008、0018、0022 与本票约束，不改资源公平性或容量政策。
