# 0020 场景准备、就绪检查与有界清理

状态：提议，等待协调者确认（2026-10-15）

## 背景

#41：本地后端未就绪会产生假测试失败。依据 ADR 0003、0004、0008、0010、0011、0015；调研见 `docs/research/scenario-prepare.md`。

## 决定

### 配置

第一版只在场景上加 `prepare` 数组；`kr run` 与 `kr gate` 共享场景执行路径。套件仍保持原样：build 在准备前完成，套件级准备会引入构建生命周期与共享范围，暂不加入。每个步骤是以下结构：

```toml
[[scenarios.login.prepare]]
run = "python3 service.py" # sh -c；后台服务必须保持前台，不自行 daemonize
# dir 相对项目根目录；默认根目录
dir = "tools"
background = true         # 默认 false，一次性命令等待退出 0
# 一次性命令的硬超时；后台步骤为就绪截止时间；默认 30s
timeout = "30s"
ready = "curl --fail --silent http://127.0.0.1:49152/health"
# 可选的项目状态清理命令；进程组终止后运行，默认硬超时 5s
cleanup = "rm -f service.port"
```

`ready` 是可选 shell 命令，仅用于 background=true；后台步骤必须有 ready，避免把 spawn 成功当成可用。固定每 100ms 探测，单次最多剩余截止时间；成功为退出 0。字段、空命令、时长、目录错误指出 `.kr.toml` 和完整键路径，给出修复办法。清理命令在该步已尝试后总会执行，包括准备失败。任一步失败后不执行后续准备和测试。

### 结论、事件与缓存

准备失败、后台提前退出、就绪超时是环境原因，场景 `passed=false`，`tests.unverified=N`，`failed=0`，不算通过也不算测试失败；有真实枚举时 N 用枚举数，尚未枚举时至少 1。`item_end.fields.unverified_reason` 必填。人读输出使用 UNVERIFIED，包含准备日志路径与检查服务配置后重试的下一步。整次运行非零，保留已有信号退出码；环境失败不新建 agent 判断点，不自动重跑准备失败。

每项 JSON 与 item_end 增加 `preparation` 数组，记录步骤序号、状态、日志、就绪日志、清理结果、耗时。现有 schema_version 保持，字段只加不改。准备步骤等同 external：任何未来结果复用必须跳过它；构建产物缓存继续有效。当前执行器本就不复用测试结论。

### 生命周期

每次运行项准备一次，围住该项现有测试和其重跑；不改重跑规则。所有准备命令通过可替换执行器。后台命令独立进程组，由作用域 guard 持有；任何退出路径逆序 SIGTERM，最多等待 5s 后 SIGKILL，并 wait 回收直接子进程，包括组长先退出但子进程尚在的情况。Ctrl-C/SIGTERM 接入现有 stop_signal，准备探测和清理必须有界，中断后不启动新项。清理命令允许在 stop_signal 已设置时执行，但仍有 5s 硬超时。清理失败使场景未验证，不掩盖已有测试结果和准备失败原因。SIGKILL 主进程不可捕获，不保证 kr 自身被 SIGKILL 后回收。

### 资源与端口

准备在场景已经拿到现有 sim/device 槽位后开始，清理完成才释放槽位，不额外申请 build/light，避免持 sim 等 build 的死锁。后台服务是该场景资源的一部分；限制为本地轻量依赖，重构建放在原有 build 阶段。

kr 不抢占端口，不杀其他进程。项目使用临时端口、独立端口文件或按实例参数隔离；ready 应核对本实例身份。绑定冲突以后台提前退出或 ready 失败记录未验证。不要固定等待代替探测，也不要把临时探测成功作为端口预留。

## 验证

主接缝为 `kr` CLI + KR_REPLAY + JSON/事件与人读快照；覆盖成功、失败、就绪超时和运行中信号，以及配置错误。进程回收用实际小进程验证（只用自身进程组）。KrSample 加临时端口小服务，按 kr lock 排队真跑一个池内场景，确认无残留。ADR 0010 第 3 层使用相同回放输入比较分类和计数；计数精确误差 0，不声称耗时性能提升。
