# 0011 kr 不内置模型：判断交给调用它的 agent，kr 负责标出、记录、验证

状态：已接受（2026-10-14，owner 确认）

## 背景
自动选测、合并辅助、失败分类、自动报告、信任策略都有「没有标准答案、需要判断」的部分。曾考虑在 kr 里内置决策模型（Cloudflare CLEF）或大模型来做这些判断。

调研（`docs/research/agent-tool-design.md`：Orca、Anthropic 的工具与 Agent Skills 指南、Beads、Arcjet、Playwright CLI、12-Factor Agents、Terraform、Kubernetes）的结论是一致的：给 agent 用的 CLI 只做确定的事，判断留在调用它的 agent 里，两者之间用 skill 连接。没有一个参考对象在 CLI 内部内置模型。

调用 kr 的本来就是大语言模型 agent。再内置一个模型会带来凭证、网络、费用和不可复现的问题，也会把 kr 绑在某个模型上，违背 ADR 0002（与工具无关）和 ADR 0010（可离线评估）。

## 决定

### 1. kr 不内置任何模型
包括决策模型和大模型。agent 想借助别的模型做判断（例如用 CLEF 分类），由它在 skill 允许的范围内自己决定，与 kr 无关。

### 2. 三层分工
- **计算层（kr）**：依赖关系、耗时、测试数、资源占用等确定的事实。
- **学习层（kr）**：从事件历史算出统计——共同失败、偶发率、失败特征库、机器速度、agent 判断的对错率。不靠模型。
- **判断层（调用 kr 的 agent）**：处理没有标准答案的部分。kr 只负责标出、记录和验证。

### 3. 判断点是 kr 输出的一等公民
- `--json` 输出有固定字段 `decisions`：每项含 `id`、问题、选项、证据（路径、统计）、kr 的默认建议及理由。
- 人读输出里，判断点单独成段，写明下一步该运行的命令。
- **会影响结论的判断点**（例如失败分类、逻辑冲突的解法）：kr 停下，用专门的退出码（暂定 4，参考 Arcjet 的「需要确认」）退出，不自行决定。
- **只影响效率的判断点**（例如加跑建议）：kr 按默认建议继续，同时记一条「待复核」。

### 4. agent 用命令交回决定，kr 记录并对账
- 交回方式：`kr decide <id> <选项> --reason "..."`，或在下一次命令上带参数（例如 `kr run --also <场景> --reason "..."`）。
- 每个决定写进事件：谁、何时、看到的证据、选了什么、理由。
- kr 事后对账并记录结果：判成偶发的，重跑是否支持；加跑的场景，是否发现了问题；合并解法，编译和测试是否通过。

### 5. 学习层与信任策略
- 学习层用这些记录让证据越来越准，例如「改了这个模块，历史上哪些场景常坏」。
- 每类判断的「agent 判对率」从对账结果算出。第三阶段的信任策略据此提出放宽建议，例如「这类判断以后不用问 owner」，owner 确认后才生效。硬底线始终写在 kr 代码里，不交给判断。

### 6. skill 由 kr 自己输出
- `kr skill` 打印与当前版本一致的使用说明：常规流程（体检 → 预检 → 运行）、每类判断点怎么判、什么时候必须问人、硬底线。主文件短，少见情况用 `kr skill --reference <名字>` 按需读（照 Orca）。
- 内容默认随 kr 版本发布。项目可以在仓库里追加（例如 `.kr/skill.md`），owner 个人可以在 `~/.config/kr/skill.md` 追加，不用发版（照 Beads 的 `PRIME.md`）。
- agent 侧只装一个很小的发现入口；各项目 AGENTS.md 只写一句「构建和测试用 kr，先读 `kr skill`」（与 ADR 0007 一致）。

### 7. 用评估改进 kr 和 skill
每批结束后，从事件看 agent 调了哪些命令、出了几次参数错、哪些判断点判错、在哪里绕了弯，据此改 kr 的输出和 skill（参考 Anthropic 的工具评估方法），并按 ADR 0010 做离线前后对比。

### 8. 时间
第二阶段第一张票先做骨架：判断点结构与退出码、`kr decide` 与记录、对账事件、`kr skill`（含追加机制）。自动选测、失败分类、合并辅助都建在这个骨架上。

## 补充（2026-10-14，复核后明确）
- **退出码 4 只用于 kr 自己下结论的命令**（`check`、`run`、`gate`，以后的选测和合并辅助）。`kr lock`、`kr pool lease` 这类透传子命令退出码的命令不使用判断点退出码。现有退出码：0 通过、1 失败、2 参数错误。
- **「停下」= 不给结论，不是中途中断**：运行照常跑完全部场景，最后不输出 PASS/FAIL，而是带着 `decisions` 以退出码 4 结束；agent 用 `kr decide` 交回后，kr 根据已有结果给出最终结论，不重跑。
- **确定规则留在计算层**：ADR 0005 的「失败 → 单独重跑一次 → 通过记偶发」和 ADR 0003 的「高负载期间失败 → 整项重跑 → 通过记偶发」仍由 kr 自动判定，不变。只有这些规则覆盖不到的情况才成为判断点（例如重跑仍失败但特征像环境问题、失败特征库里没见过）。这样同一份证据的结论不依赖 agent，判定重放（ADR 0010）可复现。第 4 条「判成偶发的，重跑是否支持」指的是 agent 在判断点上把失败判为环境或偶发时的对账。

## 不做
- 不在 kr 内调用任何模型 API，不保存模型凭证。
- 不用交互式提示问「确定吗？」。
- 不让判断结果绕过硬底线。
