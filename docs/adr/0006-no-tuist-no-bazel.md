# 0006 不采用 Tuist 和 Bazel，借鉴它们的做法

状态：已采纳（2026-10-14）

## Tuist（tuist-fit.md）
- 普通 Xcode / XcodeGen 项目的选择性测试已在 2026-01 被移除，只支持 Tuist 生成的工程。
- 选测粒度只到测试目标；Krill 32 个 UI 场景在同一个目标里，几乎得不到收益。
- 借鉴：哈希输入的计算方式、只在通过后记录哈希、提供 `kr hash` 调试命令。

## Bazel（bazel-fit.md）
- 每个工作区一个服务，资源调度管不到别的工作区，全机锁问题仍在。
- 测试缓存按目标，Krill 一样难命中；没有模拟器池；Xcode 16 起 SwiftUI 预览在 Bazel 工程里不可用；迁移和维护成本只适合有构建团队的大公司。
- 借鉴：内容寻址缓存、只缓存通过、rdeps 选测、偶发重试次数、测试大小与硬超时、资源标签、BEP 式事件流、以后的远程执行。

## 何时重新评估
项目拆成多个 UI 测试目标，或需要跨多台机器共享二进制缓存时。
