# 0012 信任和权限由用户与 agent 宿主管理，kr 只管工具层自己的规则

状态：提议（2026-10-14，owner 已确认，待协调者确认）

## 背景
spec 原第三阶段有「信任策略执行」：硬底线拦截 / 需要批准 / 自主三档，并按 agent 判对率提出放宽建议（ADR 0011 第 5 条）。

复核时对照了实际使用的工具：
- Orca 的 CLI 和 skill 没有权限分档，也不管 agent 能做什么。它只有写死在程序里的安全规则（例如只有确凿的退出证据才允许停止、放弃或重试）和 decision gate（记录要做的决定和选了什么）。
- 三档权限加按证据放宽，agent 宿主已经完整提供：Claude Code 的 `allow` / `ask` / `deny` 权限规则，以及根据历史调用建议放宽允许名单的 skill；Codex 的 approval policy 和 sandbox 也是同一类机制。

kr 再做一套，owner 就要维护两套权限，两套还会互相冲突，也违背 ADR 0002（kr 不重复开发工具的职责）。

## 决定
1. **信任和安全规则属于用户和宿主**：由 owner 写在 AGENTS.md 和宿主的权限设置里，kr 不提供权限分档、批准记录和放宽建议。
2. **kr 只管工具层自己的规则**：只有 kr 能按含义判断的硬底线，写在对应命令的代码里，例如只操作模拟器池里的设备、数据隔离检查只允许 CloudKit Development、凭证不出现在日志里。宿主只能按命令文字匹配，做不了这类检查。以后新的硬底线写在对应命令的票里，不作为单独的功能。
3. **判对率只作为数据**：ADR 0011 学习层算出的每类判断的 agent 判对率，放在 `kr report` 里。owner 据此自行决定是否在宿主里放宽权限。

## 影响
- 修改 ADR 0011 第 5 条：不再由 kr 的信任策略提出放宽建议。
- spec 第三阶段删去「信任策略执行」，「模型」一节的「信任策略」改为「工具层规则」。
