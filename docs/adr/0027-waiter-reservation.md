# 0027 被信号杀掉的排队者保留原排位 10 分钟

状态：已采纳（2026-11-14，#81）

## 背景

两周里 116 次 `kr lock` 在排队时被信号杀掉，多为 agent 的工具超时，合计丢掉 1023 分钟已排队时间。其中 60 次在 30 分钟内用同一 task、同一 worktree 重新排队，只能排到队尾。

ADR 0004 的队列里，一张票就是队列目录下的一个文件，由排队进程持文件锁。没人持锁的票属于已经不在的排队者，扫描时删除。被捕获的信号（SIGINT、SIGTERM、SIGHUP）让 kr 删票后退出；SIGKILL 留下没人持锁的票，下一次扫描删除。两种情况都丢掉排位。

## 决定

- 排队者被信号杀掉时，它的票留在原处，成为**保留位**。保留位以（资源、task、worktree）为键：资源由所在的队列目录决定，task 和 worktree 记在票里。worktree 是项目配置所在目录，没有项目配置时是当前目录，与调用日志的请求者一致（ADR 0016）。
- 同键的请求在保留期内再来时，接管这张票：锁住同一个文件，改写为自己的进程和信息，文件名不变，所以排位不变。`started` 沿用原值，`kr queue` 显示的已等待时间包含被杀之前的部分。`slot_acquired` 事件的 `resumed_place` 记录这次是否接回了原排位，用来核对收益。
- 保留位不是排队者。计算排位和空槽时不算它，所以轮到它时主人不在，后面的排队者照常拿槽位，不多等一次轮询。它不能挡住队列。
- 保留期 10 分钟，从排队者最后一次活着算起。排队者每次轮询（0.5 秒）更新票的修改时间，所以文件的修改时间就是它最后活着的时间。SIGKILL 不能被捕获，这样也能得到被杀的时刻，不需要在票里另记字段。超过保留期的保留位在下一次扫描时删除；同键的请求随后排到队尾。
- 没有 worktree 的票（旧版 kr 写的票）不保留，照旧删除。
- `kr skill` 写明：预计等待超过工具超时时间时，把 kr 放到后台运行。保留位只是兜底，不能代替这一条。

## 不做的

- 不做可配置的保留期。10 分钟是票里给的值。票里的数据只有「同键 30 分钟内回来 60 次」，没有回来间隔的分布；有了 `resumed_place` 的事件后再按数据调整。
- 不在 `kr queue` 里列出保留位。它不占槽位，也不影响任何人的预计等待。
- 不给运行中被杀的任务（exit 143/137/130）保留什么：它们已经拿到槽位，槽位按 ADR 0004 归还。
- 不改旧全机锁队列（ADR 0009）。等旧锁时还没有 kr 的票。

## 并发

接管和扫描都要先拿到票的文件锁，所以二者互斥。扫描拿到锁后才判断是否过期并删除；接管方拿到锁后核对路径仍指向同一个文件（设备号和 inode），防止接管一张刚被删除的票，再核对键和保留期。两个同键请求同时到来，只有一个能锁住票，另一个排到队尾。

## 验证

- `crates/kr-resource/tests/pool.rs`：同键接回原排位；不同 task 或 worktree 不接管；过期后删除并排到队尾；轮询会刷新保留期；保留位在队首时空槽直接给下一个排队者。
- `crates/kr/tests/lock.rs`（真实 kr 进程）：SIGTERM 和 SIGKILL 杀掉排队者，同键再来排位不变且先于后来者运行，事件记录 `resumed_place: true`；票的修改时间改到 11 分钟前后再来，排到队尾；保留位在队首时，占用者释放后下一个排队者在 1.5 秒内开始运行。
