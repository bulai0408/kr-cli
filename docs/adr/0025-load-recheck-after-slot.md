# 0025 取槽后再读一次负载

状态：已采纳（2026-10-21，#56，协调者已确认）

## 背景

ADR 0022 的取锁顺序是「负载检查 → 旧锁 → kr 槽位」，负载只在入队前读一次。排队可能要几分钟，这期间负载会变：Conflux AF-09 入队时 1 分钟负载 12.46，取得 build 槽时已到 170.21。另一次被拒的任务没有留下判定用的那次读数，事后无法核对。

## 决定

- 重活（build / sim / device）取得槽位后、启动命令前，再读一次负载与内存压力。
- 判定规则不变，仍是 `Hardware::must_wait`：默认只在内存压力 critical 时等待；`[load] block = true` 时，1 分钟负载高于 `per_core` × 核数也等待。ADR 0003「默认不因负载阻塞」不变。
- 这次读数要等待时，先放回槽位和旧锁，再从头排队（重新做入队前的负载检查、旧锁、槽位）。不持槽等待，否则排在后面的任务也被卡住。
- 从开始排队算起超过 `[load] max_wait` 后不再放回，照常继续，与入队前检查的超时语义一致。
- 读数一律写进事件：`slot_acquired.load_sample`（load、pressure、threshold），放回槽位时另写一条 `load_wait`，带 `after_slot: true` 和同一份 `sample`。读不到负载时照常继续，`load_sample` 为 null。

## 不做的

- 不区分本任务自己引起的负载（例如本任务刚启动的模拟器）。读数在命令启动前，本任务的命令此时还没运行；同一 run 里先前步骤留下的负载仍会算进去，没有数据前不做区分。
- 不改默认阈值和默认 `block = false`。

## 验证

`crates/kr/tests/lock.rs`：入队前负载低、取槽后高、再次排队后低 → 命令只运行一次，事件里有那次 99.00 / 阈值 32 的读数；默认不阻塞时取槽后读到高负载照常运行，并在 `slot_acquired` 记录这次读数。
